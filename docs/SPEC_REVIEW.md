## A. 事実と食い違っていた点（修正済み）

**A1. LOGIN の `x1` を付けると Floodgate の自動マッチに入れない**（§6.5、§8）
v0.2 は `extended_mode = true` を既定にし、「拡張モードなら評価値コメントを付けられる」としていた。shogi-server は LOGIN 行に 4 つ目のトークンがあると `Loginx1` に切り替わり、パスワード欄 `<ゲーム名>,<trip>` から `%%GAME` を自動発行する処理（`LoginCSA`）を通らない。一方、指し手のコメント（`,'...`）はプロトコルに関係なく受理される。既定を false にし、コメント送信を `extended_mode` から切り離した。
そのまま実装していたら、Floodgate に LOGIN はできるが対局が始まらない状態になっていた。

**A2. cshogi の千日手判定は対局規則には使えない**（§6.6）
`Board.is_draw()` は同一局面の 2 回目の出現で `REPETITION_DRAW` を返す（玉の往復 4 手で成立することを確認）。探索向けの判定で、4 回で成立する対局規則とは違う。LocalReferee は出現回数を自前で数えることにした。
そのまま使うと、ローカル対局が数手の往復で千日手終局になる。

**A3. 相手の評価値コメントは対局中に届かない**（§6.5）
サーバは対局者には `<指し手>,T<秒>` だけを中継し、コメントは棋譜ファイルに書く。「相手のコメントを UI で反転表示」は通常は発生しない経路なので、前提を書き換えた（解析だけは残す）。シナリオ 13 の後半は偽サーバがわざとコメントを中継する場合のテストになる。

**A4. 手番外に送った指し手は捨てられず、次の手番に適用される**（§6.5）
`game.rb` の Deferred 処理。二重送信や取り違えは「エラーで弾かれる」のではなく「次の手として勝手に指される」。I7 の重要性が上がるので明記し、偽サーバにも同じ挙動を持たせて誤送信を検出できるようにした（シナリオ 22）。

## B. 未決事項のうち解決したもの

**B1. フィッシャー加算のタイミングと `T` の丸め**（§6.4）
`process_time`: `mytime += fischer; mytime -= t`。`t = max(floor(経過), least_time_per_move)`。時間切れは `mytime - t + byoyomi + fischer <= 0`。つまり加算分はその手に使え、`T` は秒未満切り捨て、残りがちょうど 0 になる着手は負け。Floodgate 本番での検算は未決に残した。

**B2. キープアライブ**（§6.5）
サーバは空行に空行で応答する。30 秒規則はサーバ側では未検査だが規約にはあるので、既定 60 秒・下限 30 秒にした。

**B3. 入玉宣言の判定機能**（§6.6）
cshogi に `is_nyugyoku(rule)` / `nyugyoku_result(rule)`（`LAW_27` / `LAW_24`）がある。自前実装は不要で、`core/nyugyoku.py` は薄いラッパにする。24 点法（31 点以上で勝ち、24〜30 点は引き分け）も同じ API で扱えるので、M9 は小さく済む。

## D. 構成の変更（§5.5、§9）

- **偽物を `src/takeover/fakes/` へ**。`python -m takeover fake-server` は `tests/` を import できないため。
- **インターフェースの切り出し**（`engine/base.py`、`transport/base.py`）。GameCore の差し替え点を固定し、複数人（複数モデル）で並行して実装できるようにした。
- **スクリプト式エンジンの追加**。v0.2 は「偽エンジンの遅延を調整して同着を再現」としていたが、子プロセスの遅延は結局タイミング頼みで、「sleep に頼らない」と両立しない。GameCore のレースはキューへの投入順で再現し、子プロセスの偽エンジンは EngineController のテストに専念させる。
- **純関数の分離**（`usi_parse.py`、`csa_parse.py`、`ui/messages.py`）と、**配線の分離**（`app.py`）。
- **ソークテストのマーカー化**。1000 局を毎回の `pytest -q` に入れると開発の往復が遅くなる。

骨組みには、依存の向き・スレッド不使用・インターフェースの一致を見張るテスト（`tests/test_skeleton.py`）を付けた。

## E. ユーザーの判断が必要なもの

1. **§7 の確認事項 Q1〜Q9**（SPEC §12）。どれも安全側の仮決め案を付けてある。特に判断が分かれそうなのは次の 3 つ。
   - **Q4**：TimeGuard 発動中の再奪取を拒否する（拒否しないと AUTO ⇔ MANUAL を往復する）。
   - **Q5**：秒読み・加算が TimeGuard の閾値以下の対局では、持ち時間を使い切った後に MANUAL が使えなくなる。例の設定（300 秒＋10 秒加算、閾値 15 秒）でも、残りが少なくなると同じ状態になる。警告だけにするか、閾値を対局条件から自動で決めるか。
   - **Q6**：CSA モードの ponder 開始をエコー受信後にする。
2. **評価値コメントの符号**。2026-11-10 に「指した側視点」と決定済みだが、Floodgate の慣例は先手視点だったという記憶がある（未検証）。慣例と違うと、Floodgate 上の評価値グラフが後手番のとき反転して見える。設定で切り替えられるようにしてあるので、既存クライアントか Floodgate の棋譜で確認してから既定値を決めたい。
3. **`extended_mode` の扱い**。x1 が不要と分かったので、設定項目ごと削除してもよい（今は false 既定で残してある）。
